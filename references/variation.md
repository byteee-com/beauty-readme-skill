# 变奏系统

风格卡给出的是**方向**，不是模板。同一张风格卡用在两个项目上，产出应当一眼能看出是两套设计。
本文件规定"在风格卡之内还能变什么"，以及怎样避免每次都落到同一个默认解。

> 多样性的来源优先级：**项目证据 > 概念 > 风格卡 variants > 全局变奏轴 > 种子**。
> 种子只用来在"同样合理"的选项之间打破平局，绝不能压过证据和概念。

---

## 1. 四层自由度

| 层 | 决定什么 | 来源 |
|---|---|---|
| **风格卡** | 视觉语言、禁区、张力规则 | `styles/*.yaml` |
| **骨架** | README 的阅读顺序与重量 | 风格卡 `skeleton`（默认）或 `alt_skeletons`（兼容） |
| **变体（variants）** | hero 的构图方式 | 风格卡 `variants`，每张卡 2–4 种 |
| **全局变奏轴** | 画布比例、锚点、配色来源、字体性格、质感、密度、深色诠释 | 本文第 2 节 |

风格和骨架**解耦**：瑞士网格可以配海报骨架，霓虹终端可以配宣言骨架。只要风格卡 `alt_skeletons` 列出了该骨架，就是合法组合。

## 2. 全局变奏轴

每一轴先看风格卡有没有限制（`variation_limits`），再看概念需要什么，最后才用种子挑。

| 轴 | 可选值 | 由什么决定 |
|---|---|---|
| **画布比例** | `1280×360` 横幅 · `1280×480` · `1280×640` · `1280×720` · `1280×800` | 物件形状：登机牌、条幅偏扁；海报、论文首页偏高 |
| **构图锚点** | 左重 · 右重 · 下沉 · 中轴 · 对角 · 出血裁切 | 物件的"阅读方向"：时间线左→右，地层上→下 |
| **配色来源** | 品牌色 · 截图取色 · 生态色 · 物件本色 · 单色 + 一点 | 有品牌用品牌；没有时优先**物件本色**（蓝图青、牛皮纸、荧光粉），生态色是最后手段 |
| **字体性格** | 新怪诞无衬线 · 衬线 · 等宽 · 压缩无衬线 · 圆体 · 像素 · 中文宋 / 黑 / 楷 | 项目语气：严肃规范 → 衬线 / 怪诞；玩具感 → 圆体 / 像素 |
| **质感** | 平涂 · 颗粒 · 网点 · 扫描线 · 纸纹 · 套印错位 · 无 | 风格卡允许范围内选一种，全套统一 |
| **密度** | 极简（≤ 3 个元素）· 平衡 · 信息密集（规格表、仪表） | 证据量：证据多就密，证据少就空，不用装饰补 |
| **深色诠释** | 夜景 · 发光屏 · 负片 / 晒图 · 荧光油墨 · 同场景换时间 | 必须是"换场景"，不是反色 |

记录方式：在 DESIGN.md 写一行 **变奏签名**，例如：

```
blueprint · document · variant=exploded-view · 1280×640 · 下沉 · 物件本色 · 等宽 · 纸纹 · 平衡 · 负片
```

## 3. 混搭（可选）

当第二名风格同样合理，或主风格单独用显得平淡时，可以**从第二名借一个元素**：

- 骨架、token、字体、禁区全部来自**主风格**；
- 只借**一个**元素，且必须出现在借出方风格卡的 `borrowable` 列表里；
- 借来的元素要用主风格的配色和线条重画，不得保留借出方的配色；
- 借出方 `forbid` 中与主风格冲突的条目，以主风格为准。

示例：

| 主风格 | 借用 | 结果 |
|---|---|---|
| 瑞士网格 | 霓虹终端的"真实输出片段" | 网格规格书里嵌一块黑白命令输出，替代元数据栏 |
| 学术论文 | 蓝图的"尺寸标注线" | 论文 Figure 1 用标注线标出模块维度 |
| 便当格 | 孔版印刷的"套印错位" | 只给最大那一格做双色错位，其余格保持平涂 |

不许借两个以上；借了就在变奏签名里写 `+ borrow:{style}.{element}`。

## 4. 种子：在平局时做选择

`analyze_repo.py` 用仓库名计算一个确定性种子，在**同样合理**的变体之间挑一个，并输出在 `variation` 字段里：

```bash
python3 scripts/analyze_repo.py <repo> --json            # 默认种子 = 仓库名哈希，结果可复现
python3 scripts/analyze_repo.py <repo> --json --seed 7   # 用户说"再来一版 / 换个感觉"时换种子
python3 scripts/analyze_repo.py <repo> --json --exclude swiss-grid   # 用户说"不要这种"时排除
```

规则：

1. 种子的结果是**起点**。如果概念明显需要另一个变体（比如物件是长条形票据却抽到了 `1280×800`），直接改，并在理由里写一句。
2. 用户说"再来一版"时，**至少换两条轴**（例如变体 + 配色来源），只换颜色不算新方案。
3. 多方案对比模式下，三张缩略稿必须分别来自**不同风格卡且不同骨架**；脚本的 `compare_set` 已按此挑选。

## 5. 反默认指纹

Agent 有自己的惯性。下列组合出现 **3 条以上**时，视为"又做成了默认解"，必须换掉至少两条再出图：

- [ ] 画布 `1280×640`
- [ ] 左侧标题 + 右侧物件 / 窗口
- [ ] 标题字体是 Inter / Helvetica / 系统无衬线
- [ ] 背景是纯白或 `#0D1117` 一类近黑
- [ ] 唯一强调色是蓝色或绿色
- [ ] 所有元素水平放置，没有任何旋转、裁切或叠压
- [ ] 小标签全大写 + 加宽字距
- [ ] 右上角一行元数据（`v1.0 · MIT · TypeScript`）

这份清单不是禁令，单独出现任何一条都没问题；问题在于它们**总是一起出现**。

---

## 6. 变体之间要"结构不同"

判断两个方案是否真的不同，用这三问，至少两问答"是"：

1. 把两张图都缩成 100px 宽的灰度缩略图，轮廓还能区分吗？
2. 读者的视线起点在不同位置吗？
3. 主体物件不同，或同一物件的呈现方式不同（正视 / 剖视 / 爆炸图 / 局部特写）吗？

只换配色、只换字体、只换背景纹理，三问全是"否"——不算变体。
