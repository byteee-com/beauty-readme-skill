# README 信息架构与文案

访客在 README 首屏平均停留不到 10 秒。结构的唯一目标：**让人尽快回答"这是什么、对我有没有用、怎么开始"**。

## 1. 通用阅读顺序

```
1. 身份      名称 + 一句话定位（hero 或标题）
2. 价值      解决什么问题 / 和替代方案有何不同（≤ 3 条）
3. 证据      真实截图、真实命令输出、真实用户或案例（有才放）
4. 开始      安装 + 最小可运行示例（可复制）
5. 用法      常见场景、配置、API 概览
6. 边界      依赖、平台、限制、非目标
7. 社区      贡献、许可证、致谢
```

不同骨架会调整顺序和重量（见 `skeletons/`），但**"开始"不能晚于首屏后第二屏**。

## 2. 一句话定位

公式：`{名称} 是一个 {形态}，帮助 {谁} {做成什么}。`

- ✅ "fd 是一个命令行文件查找工具，比 find 更简单、更快。"
- ❌ "A blazingly fast, modern, next-generation solution for all your needs."

规则：
- 写具体结果，不写形容词堆砌（blazing / next-gen / powerful / seamless）
- 不超过 25 个英文单词或 40 个汉字
- 和 `package.json` / 仓库 About 描述保持一致；如不一致，提醒用户同步

## 3. 价值点

- 最多 3 条，每条 = 加粗短语 + 一句解释
- 每条最好能指向证据（一个命令、一张图、一个链接）
- 不能证明的价值点改写为描述性语言，或删除

## 4. 快速开始

- 第一个代码块必须可以直接复制运行（不要带 `$` 提示符，或明确使用 `console` 语言标记区分输入输出）
- 多种安装方式时：最常用的一种放在外面，其余放进 `<details>`
- 最小示例 ≤ 10 行，并展示真实输出

````markdown
```bash
npm install mytool
```

```js
import { run } from 'mytool'
await run('./input')   // → 输出 ./dist/result.json
```
````

## 5. 徽章

- 最多一行，只放有信息量的：版本、CI 状态、许可证、（可选）下载量
- 位置：hero 下方或标题下方居中
- 统一使用 shields.io 同一 `style`；颜色可用 `color=` 对齐设计规范强调色

## 6. 必须保留

改写时下列内容只可重排或精简，不可删除（删除需告知用户）：

- 许可证声明、版权
- 安全报告方式（SECURITY）
- 贡献指南链接、行为准则
- 致谢、赞助、第三方声明
- 已有的徽章链接目标
- 任何法律、合规、隐私相关文字

## 7. 多语言

- 若已有多语言 README（`README.zh-CN.md` 等），在顶部提供语言切换行，并**同步结构**；视觉资产中的文字按语言拆分目录：`assets/readme/en/`、`assets/readme/zh-CN/`
- 不主动新增翻译，除非用户要求

## 8. 文案语气

- 跟随项目已有语气（严肃 / 轻松 / 学术）
- 使用主动语态、第二人称
- 术语首次出现时给一句解释
- 删除重复：同一事实只在一处完整表达
